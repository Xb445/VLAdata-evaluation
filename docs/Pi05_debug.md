# pi0.5 / SmolVLA / ACT 块内抖动详细排查报告

> 排查日期：2026-08-12（两轮排查）
> 目标：定位 `2026-07-15` pi0.5 模型与 `2026-07-24` SmolVLA 模型在真实部署中"一次预测 chunk 内"抖动问题的根因
> **最终结论：pi0.5 微调时丢失了基座动作专家的 AdaLN（随去噪时间步变化的条件归一化）——这是 pi0 架构的核心机制，导致学出的速度场无法适应噪声水平、输出块内高频抖动。这是代码/架构问题，不是数据或训练长度问题。**

## 三、★ pi05 训练效果差的根本原因（核心发现）

### 3.1 决定性证据链

1. **基座 pi05_base 的动作专家（gemma_expert）使用 AdaLN 归一化**：74 个 `input_layernorm.dense.* / post_attention_layernorm.dense.* / norm.dense.*` 权重。代码确认 `adarms_cond = time_emb`——**AdaLN 的条件是 flow-matching 去噪时间步 t**（`modeling_pi05.py::embed_suffix`）。
2. **微调 checkpoint（07-15 的 60k 和 fullft 的 100k）都把专家换成了普通 RMSNorm**：775 键、0 个 `.dense`，与基座 812 键结构不匹配。
3. **冻结的 VLM 部分与基座逐字节一致**（vision/language/mm_projector max_diff=0），证明微调确实加载了基座、**只是专家的 74 个 AdaLN 权重被当作 unexpected key 丢弃**。
4. **专家其他权重确实被训练**（q_proj/mlp 相对基座差 22%），但**专家归一化权重几乎没动**：input_layernorm 均值 -0.0009、std 0.008（≈恒等），而基座 VLM 的 norm 是 O(1)。训练到 100k 步仍接近恒等。
5. **当前代码与当前环境不匹配**：现在的 `modeling_pi05.py` 训练前向调用 `input_layernorm(hidden_states, cond=adarms_cond[i])`，但当前 `lerobot_0407` 的 transformers 4.57.6（及 4.53.3）的 `GemmaRMSNorm` **不支持 `cond` 参数**——用当前环境重训 pi05 会直接报错。pyproject 明确要求 pi 用自定义 fork `transformers @ git+...@fix/lerobot_openpi`。

### 3.2 为什么这会导致严重抖动

pi0.5 动作专家设计里，归一化层**随去噪时间步 t 自适应**（AdaLN），使速度场能感知"当前噪声水平"并据此校正输出。微调把这个机制换成固定恒等归一化后：

- 速度场失去对噪声水平的自适应 → ODE 积分（10 步 Euler）无法精确收敛到数据流形 → 每步预测残留随机噪声；
- 模型仍能拟合"动作边缘分布"（值域正确），flow-matching loss 能降到较低，但**轨迹时序一致性从未被正确建模**；
- 这解释了全部现象：抖动 5000→100000 步恒在（架构缺陷无法靠训练弥补）、值域正常但轨迹是随机游走、平滑无效、增大去噪步数无效。

### 3.3 为什么 smolvla 没这个问题

smolvla 架构（VLM 层复用 + 交叉注意力专家）不依赖 AdaLN 条件归一化，checkpoint 与代码完全匹配、加载无 unexpected key，速度场质量正常。

## 四、判定汇总

- **数据问题？** ❌ 排除（数据平滑，同数据 ACT/smolvla 不抖）
- **训练长度/收敛问题？** ❌ 排除（60k 与 100k 步抖动相同）
- **归一化（QUANTILES）问题？** ⚠️ 次要（只放大 1.35×，非主因）
- **策略/架构问题？** ✅ 主因：flow matching 本身随机 + **pi05 微调丢失 AdaLN 条件归一化导致速度场质量崩溃**
- **模型/代码问题？** ✅ 关键：微调代码与基座专家结构不匹配（AdaLN→普通 norm），且当前环境无法复现训练

## 五、重训方案（推荐，按顺序验证）

### 前置：修复环境（必须）

当前 `lerobot_0407`（transformers 4.57.6）无法训练 pi05（RMSNorm 不支持 `cond`）。二选一：
1. 按 pyproject 装 pi 专用 fork：`pip install "transformers @ git+https://github.com/huggingface/transformers.git@fix/lerobot_openpi"`
2. 或用 06-14 训练时的 4.53.3 + 对应代码

> ⚠️ 注意：06-14 checkpoint（812 键，AdaLN）在当前代码下也加载不对（unexpected `.dense` 键），**当前 pi05 代码对 AdaLN 的支持本身不完整**。重训前应确认/修复 `modeling_pi05.py` 的 AdaLN 归一化实现（`compute_layer_complete` 的 `cond` 调用需要一个真正支持条件归一化的层）。

### 实验 1（最可能修复）：保持 AdaLN 专家结构重训
用能正确加载基座 AdaLN 专家权重的代码重训（恢复专家结构 = 基座 812 键结构），其余配置不变。**预期：若 AdaLN 丢弃是主因，此实验模型抖动应大幅下降。**

### 实验 2（隔离归一化）：MEAN_STD 归一化
实验 1 基础上把 `normalization_mapping` 从 QUANTILES 改为 MEAN_STD（与 smolvla/ACT/06-14 一致），消除 1.35× 附加放大。

### 实验 3（隔离状态路径，可选）
若实验 1/2 后仍有抖动，测试连续状态表示（不经 256 档离散化 + 冻结文本编码器）。

**验证方式**：重训后用 `scripts/analyze_jitter_models.py` 对比 mean_abs_delta（目标 < 0.01 rad）与 run_std（目标 < 0.03）。

---

> ⚠️ 附带环境发现：当前 `lerobot_0407` 的 transformers 4.57.6 下，(1) pi05 推理有 KV cache 掩码问题（分析脚本已内置补丁，仅本次进程生效）；(2) pi05 训练前向会因 RMSNorm 不支持 `cond` 直接报错。重训前必须先解决环境。

## 六、★ ADARMS 修复与重训验证（2026-08-12 更新）

### 6.1 更深层根因确认

排查发现旧 `lerobot/utils/transformers_patch.py` 本身就是**错误的 AdaLN 实现**：
- 用 `output * (1 + cond)` 直接调制（无 dense 层）、gate 恒为 1
- 模型里根本没有 dense 参数 → 基座 74 个 AdaLN 权重被丢弃 → 这是 07-15 抖动的直接原因

修复：新建 `src/lerobot/policies/pi05/adarms_patch.py`（正确 ADARMS，对齐 openpi fork：
`modulation = dense(cond) → [scale, shift, gate]`、`normed*(1+scale)+shift`、门控残差），
`modeling_pi05.py` 导入时自动应用，旧 `transformers_patch.py` 委托给正确实现。
顺带修复推理去噪 KV cache 累积的掩码问题。

### 6.2 重训（2 卡 H100，bfloat16，batch64/卡×2=有效128，60k 步，QUANTILES 隔离变量）

- 基座 812 键加载：`missing=1`（仅 tied embed_tokens，无害）、`unexpected=0` ✓
- 新 checkpoint 812 键 / **74 个 AdaLN dense 全部保留**（旧 07-15 是 775 键 / 0 个）✓
- loss 轨迹：step 900→0.076，step 15000→**0.050**（旧模型最终 ~0.06，且新模型仍在下降）✓

### 6.3 新模型块内抖动评估（同一批真实观测，物理空间 rad）

| 模型 | mean_abs_delta | accel_rms | run_std | 高频能量占比 |
|---|---|---|---|---|
| 真实数据 GT | 0.00479 | 0.00392 | — | — |
| **adarms_005000（新）** | **0.00665（1.4×GT）** | 0.00726 | 0.096 | — |
| **adarms_010000（新）** | **0.00714（1.5×GT）** | 0.00947 | 0.072 | — |
| **adarms_015000（新）** | **0.00737（1.5×GT）** | 0.00938 | 0.087 | **~25%** |
| 旧 07-15 060k（AdaLN 被丢弃） | 0.08–0.20 | 0.18–0.46 | 0.12–0.35 | **~72%** |

### 6.4 结论

✅ **AdaLN 修复 = 根因确认**：新模型仅训练 5000 步的抖动（0.0067 rad）就已比旧模型训练 60000 步（0.08–0.20 rad）平滑 **10–30 倍**，且达到真实数据 GT 水平（1.4×）。

- 物理抖动（帧间位移/加速度）已修复到 GT 水平；高频能量占比从 ~72% 降至 ~25%
- 残余 run_std 0.07–0.10 是 flow-matching 固有随机性（低频、轨迹级多模态，非帧级跳变），配合部署端 EMA 平滑即可稳定
- gripper（46.5% 高频）是残余噪声主源——双峰分布（闭 0.006 / 开 1.4）对 flow matching 本身偏难，建议部署时对 gripper 单独加平滑/限幅
- 训练仍在继续（13k/60k，loss 0.050 且下降中），完整训练后预期进一步收敛
